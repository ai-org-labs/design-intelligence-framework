# 視覚的な魅力へのフィードバック — 2026-10-11

ユーザーは提示方法に続き「センスが足りない」と指摘し、魅力を探して磨く工程の改善を依頼した。特定製品の非公開資料はこの記録に含めない。

| 不足 | 変更 | 確認すべき結果 |
| --- | --- | --- |
| 不具合点検に偏る | 視覚的魅力と使いやすさを別に評価 | 見た目への具体的な批評が出るか |
| 抽象的な配色・一貫性の評価 | 意図した印象と、文字・余白・構図などの判断を対応させる | 判断の理由を画面で理解できるか |
| 比較して選べる画面案が不足 | 同じ画面・内容で複数方向を可視化 | 色違いを超えた違いがあるか |
| 細部を磨く工程が弱い | 出力を見て批評し、有力案を修正 | 修正前後の違いが役立つか |

対象はdif-design / dif-explore / dif-ux-ui / dif-evaluate / dif-improve。dif-ux-uiに単独利用可能な参照ガイドを追加。CLI、スキーマ、成果物契約、アーキテクチャは変更しない。見た目の別案を、契約が求める操作モデルの別案の代わりに数えない。

QIF上の境界：好みを実測値にしない、参照調査を捏造しない、提案画像を観測画面としない、使いやすさと魅力を混同しない。人間の採用・Stable判定はpendingのまま。

検証はSkill形式・参照・同梱リソース整合の機械確認。実際に魅力的な案を生成できるかは、次回の比較画像と人間の判断による行動評価が必要。今回の指示改善だけで「センスが向上した」とは認定しない。

## 提案能力の具体化

続くユーザー依頼により、指示の改善に加えて独立した `dif-art-direct` Skill、参照手法、架空ブランドの3方向比較HTML・画像・推敲記録、手動評価課題を追加した。新しい責務をArchModelに記録し、固定版ArchMapで図を再生成した。上記の「アーキテクチャは変更しない」は先行したSkill文面のみの修正範囲を指す。

証拠：`examples/visual-directions/checks.json` はPC・狭幅のローカル操作確認、`review.md` は作者の画像確認。`npm run verify` と `npm run benchmark` の成功は既存の構造・CLI・機械fixtureの整合性を示す。視覚的な魅力の保証には使わない。独立試行、人間の好み、実ユーザー効果は未確認で、ArchModelのvisual-trialsはunknownを維持。
