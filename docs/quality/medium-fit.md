# 媒体の取り違えを修正 — 2026-10-11

ユーザーは「ぜーんぶおんなじ」「メニュー表ってレストランのテーブルに置いてあるアレ」「画面の中がほしい」と指摘した。作者は4用途をWeb紹介ページへ寄せ、媒体に合った一次成果物を出せていなかった。描画チェックが通ったことでは埋められない要件適合の失敗である。

修正：メニューはA4表裏2ページのPDF（編集元はHTML/CSS）へ変更。料理番号・価格・料理の生成画像を紙面に配置。生成写真は架空料理で実食材の根拠ではない。ImageGenで新規生成した素材をリポジトリへコピーし、CSSの背景位置で各料理を表示した。メニューは汎用ブラウザの応答的レイアウトではなく固定印刷寸法で確認する。

図鑑はmonster.htmlを320×240の表示そのものへ変更。筐体・広告コピー・試作操作パネルを主画面から外した。以前の紹介ページはmonster-study.htmlに記録として保持。固定データの観測であることは説明資料へ分離し、UIの中は図鑑としての文言にした。実認識やファームウェア実装という主張はしない。

実証範囲：PDFをPopplerで2ページ描画し作者が確認、pypdfでA4寸法と主要文字を検査。Web画面の原点と320×240寸法、発見→保存失敗→再試行→完了を確認。実機の日本語フォント・タッチ精度・消費電力、物理印刷の色と断裁は未検証。PDFは通常プリンタでの試作用で、塗り足し/CMYK等の商業印刷入稿仕様ではない。

DIFガイドに媒体・寸法・一次成果物を最初に確定する判断を追加。同梱知識、ArchModelと固定版ArchMap投影、AOF/QIFの記録を更新する。訂正案の採用はpending。以前の機械通過を満足度の根拠にしない。
