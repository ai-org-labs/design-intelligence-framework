# 4件のDIFサンプル — 2026-10-11

ユーザーが指定した4用途についてDIF Skillsの提案、視覚設計、部品、状態・損失境界、評価の方法を適用。今回の作者が作成したサンプルであり、独立エージェントによる盲検試験や利用者調査と称さない。

| 要求 | 成果物 | 観測と限界 |
| --- | --- | --- |
| イタリアンメニュー | Casa Tutti、架空の料理/税込価格、分類 | Webの分類・説明・幅別描画。実店舗の料理/食材情報ではない |
| 革新的メーカーのHP | AER、独自製品SVG、仕上げ/仕様 | 操作と描画。Appleの観測/資産ではなく依頼の方向性から創作 |
| M5図鑑 | FIELDNOTE、320×240、一覧/詳細/観測/記録 | Web寸法と保存失敗/回復。公式CoreS3の検索本文を参照、実機未検証 |
| 銀行入金フロー | NAGI、認証/ホーム/口座/待機/完了、代替案 | 模擬認証・架空イベントのみ。実銀行のセキュリティ・業務・法令適合を証明しない |

初版のPC/狭幅画像を保存し作者が目視。メニューのはみ出し/短い折り返し、異なる料理の配色、銀行見出しの改行、図鑑の通知欄を修正。長いページの画像取得不良は取得方式を修正。美的品質と使いやすさの向上は自己判断で、測定値ではない。

common.js/base.css/art.jsを共有し、製品固有の見た目と状態を各ファイルへ分離。共通化だけで保守性を実証したとは扱わない。ローカル確認はchecks.jsonに記録し、失敗入力・通信不明・未着金を成功と誤認しない。銀行イベントの一回反映はメモリ内であり、本番の冪等性ではない。

設計正本studies.archmodel.yamlは4製品の責務/方向/代替/依存を記録。固定版のArchModel/ArchMapでarchitecture.svgを生成し、採用検証はunknownを維持。DIF本体のArchModelにも成果物参照を追加。AOF台帳とQIF構造検証を実行。Stable、人間の採用、Finalizeの完全な非認証契約は主張しない。
