# DIF / Four design studies

[4件の一覧を開く](index.html)。依頼された4つの用途に、DIFのdif-design / dif-art-direct / dif-ux-ui / dif-controls / dif-evaluateの方法を適用した作者による提案。独立エージェントの盲検評価や、人間による採用結果ではない。各サンプルは1つの主案を具体化し、代替方向は下表の仮説に留めた。銀行はフローの代替案を別記。

| サンプル | 主案と根拠 | 比較した代替方向（未制作） | 操作 |
| --- | --- | --- | --- |
| [Casa Tutti](menu.html) | 生成り・深緑・赤、料理イラストと価格を揃えた家族の食卓。分類とシェア提案を両立 | 写真中心の大型メニュー：食感を伝えやすいが、実料理の撮影・更新が必要 | 分類切替、食材説明、ブラウザ印刷 |
| [AER](device.html) | 機能数より暮らしの余白。大きな見出し・金属の立体表現・静かな発光 | 技術仕様中心：比較検討には強いが、初見の製品体験が弱まる可能性 | 仕上げ切替、セクション移動、仕様モーダル |
| [FIELDNOTE](monster.html) | フィールド機器のオレンジ筐体、明るい図鑑面、オリジナルのドット絵 | 濃色のゲームHUD：雰囲気は強いが小文字・情報過密を招きやすい | 一覧・詳細・次の種・観測デモ・記録・失敗再試行 |
| [NAGI](bank.html) | 状態を明確にし、着金前後を混同しない穏やかな銀行 | 連携による入金支援：転記削減の可能性と外部依存。[詳細](bank-flow.md) | 模擬ログイン・失敗・入力・確認・模擬着金・明細 |

## 表現と実装

料理・端末・モンスターはオリジナルSVG/CSS。写真、実機製品、Appleの画面・資産の転載ではない。Appleの参照は「製品中心の明確な階層」という依頼意図として解釈し、現在のAppleサイトを視察したという主張はしない。登録商標・実販売・性能測定を示す意匠ではない。

フォントはOS書体＋Georgia/和文明朝fallback。配布フォントなし。OS別の実字形・ウェイト差は未評価。見出し/本文/価格/端末表示を役割で使い分ける。イラストの料理と食材は架空で、アレルギーの実判断に使わない。

M5StackはCoreS3を仮定。[公式資料](https://docs.m5stack.com/en/core/CoreS3)の320×240・タッチ画面という仕様を2026-10-11に公式検索本文で確認。画面座標は320×240、外側の筐体は独自の説明用意匠。実機に同じ筐体や描画結果があるという意味ではない。図鑑の種一覧は予習可能なカタログとし、「記録済み」は観測記録の有無を示す。ドット絵はブラウザSVG、ファームウェアへの変換・日本語フォント容量・タッチ・消費電力は未測定。

## 部品とカスタマイズ

| 正本 | 利用箇所 | 変えられるもの／守るもの |
| --- | --- | --- |
| base.css / common.js | 4サンプル | 共通focus、motion軽減、dialog、DOM生成。各製品の表現は各CSSへ分離 |
| art.js / menu.js | 料理カード6枚、図鑑3種 | データから反復表示。価格/食材、種の情報を変更可。実データと混同しない |
| 各製品CSSの変数・役割class | 各画面と状態 | 色や表面、文字役割。bankの完了条件は見た目のvariantにしない |
| bank.jsのstateとaction/line部品 | 5画面＋失敗状態 | 画面遷移とイベント処理を分離。入金完了は模擬イベントのみ |
| monster.jsのbtn/画面renderer | 図鑑状態 | 記録の成功と表示更新を連動。失敗時は発見数を増やさない |

小さな同梱試作として共通化した範囲で、汎用UIライブラリの公開APIではない。イベント・保存キー・画面ID変更時は全利用箇所とchecksを確認する。bankの状態はメモリ、図鑑は名前空間付きlocalStorage。サーバー、依存ライブラリ、ビルドは不要。イラスト生成と商品データの変更、部品テーマの変更と金融状態の変更を混同しない。

## 自己レビューと修正

初版はrenders/v1-*.pngに保持。実際に描画し、以下を修正した。

| 所見 | 修正 | 残る課題 |
| --- | --- | --- |
| 狭幅メニューの皿が横へはみ出した | 狭幅の回転と余分な負の余白を解除。見出しと料理を縦に配置して短すぎる改行も解消 | 料理の食感はイラストでは十分に伝わらない |
| トマトとクリームの絵が同じで紛らわしい | クリームは別の配色に分離 | 本番の食材・料理写真との一致は未評価 |
| 銀行の意図した2行見出しが1行になった | 改行を保持し視線の塊を整理 | 実OSのパスキー画面と復旧は未実装 |
| 図鑑の発見画面が240px内で窮屈 | 余白と絵の高さを整理し記録通知欄を確保 | 実機2インチでの日本語可読性・指の精度は未検証 |

AERの静かな立体表現は保持。製品仕様が未定なためスペックを盛らず、その限界を仕様モーダルで示した。メーカーとしての革新性・魅力は作者の仮説であり測定結果ではない。
