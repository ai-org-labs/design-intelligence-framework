# 登録・ログインの比較提案

これは架空の要件に対してDIFの成果物契約を示すAI作成サンプルです。人間の採用判断・実ユーザーでの検証はありません。

## 前提と比較

| 項目 | A: Familiar form | B: Email-first guided access |
|---|---|---|
| 仮説 | パスワードに慣れている | 利用中の端末でメールにアクセスできる |
| 構成 | 登録とログインを分離 | メールから段階的に案内 |
| 期待効果 | 既存の理解と基盤を活用 | 入力負担を減らす可能性 |
| 制約・代償 | パスワード管理と再設定 | メール遅延、端末間移動 |
| 設計品質 | 明示ラベルと復旧導線を仕様上レビュー | 同じ基準でレビュー |
| 実現可能性 | 現行基盤が不明のため未評価 | メール基盤と到達率が不明のため未評価 |
| ビジネス価値 | 実測なし | 実測なし |

Bはこの比較内で操作方式の異なる探索案です。業界全体で新しいという主張ではありません。どちらも仮説への依存を保持しています。Aを無条件に採用する推薦はしません。

## フローと状態

[flow.mmd](flow.mmd) と [mockup.svg](mockup.svg) を参照。画面IDは画像に併記。エラーは同一画面の状態で、フローには自己遷移で示します。無効な入力では入力を保持し修正対象を文字で示します。送信中は再送を抑止し進行を通知。新規登録の確認、通常ログイン、復旧の確認を経てsuccessへ到達します。成功状態も画像に示します。

Aのパスワードは貼り付けと管理ツールを許可する設計。Bはリンク失効・未着への再送を用意。アカウント有無を第三者へ不要に開示しない文言を意図しますが、実際の認証セキュリティは未検証です。

狭幅は一列・左右16px、広幅は最大440pxのカード。タップ領域、フォーカス表示、読み上げ通知、拡大・日本語長文化時の折り返しは実装後に確認します。静的画像は挙動を証明しません。

## レビューと改善

改善前は `a-login-action` のラベルが空で、#AAAAAAと#FFFFFFの組み合わせでした。これは名前と色の宣言に対する機械検証の問題です。改善後は「Sign in」、白文字と#244FC4としました。`before.json` と `design.json` の差分、`change-label` と `evl-label-fix` を参照。

保守的改善はAの該当部品の修正。抜本的改善の比較候補はBのメール起点導線です。Bへの移行では配信・リンク期限・復旧の仕様を再設計する必要があります。変換率向上は未検証仮説です。

## 実験計画（未実施）

仮説: Bはパスワード入力負担を減らす一方、メール移動で中断が増える可能性がある。対象は新規/再訪、モバイル/デスクトップの各利用者。登録・ログイン・リンク失効からの復旧をタスクとし、成功率、誤操作、所要時間、理解、メール遅延を分けて記録。探索的ユーザーテストで問題を特定し、A/Bは同意・プライバシー・基盤確認後に割当。サンプルサイズは最小検出効果と基準率が不明のため未決定。都合のよい少数例で優劣を断定しない。配信・募集・計測はDIFの提供外です。

## 完成状態と判断

4種類のファイルは存在します。機械検証は構造と宣言を対象とし、意味的な整合性・使いやすさ・実ユーザーでの効果は未確認です。状態は `ready-for-human-review`。採否はpendingのまま保存しています。実際に受け取った判断はCLIの `decide` に入力できますが、著者の本人確認は提供しません。
