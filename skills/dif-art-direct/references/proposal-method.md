# From meaning to visible proposals

## 1. Direction brief

Write a compact brief: product promise, audience and task, context, desired impression, signature traits, non-negotiable constraints and assumptions. A named direction must have a reason to exist beyond a visual trend.

For every direction connect:

| Meaning | Design mechanism | Expected response | Cost / uncertainty |
| --- | --- | --- | --- |
| A quiet pause | Slow visual rhythm, limited emphasis, generous grouping | Attention settles on the product | More scrolling; the emotional effect is a hypothesis |
| Welcoming experimentation | Playful scale shifts, distinct shapes, active composition | Trying feels approachable | Can compete with the primary action |
| Confident choice | Clear index, comparative details, disciplined alignment | Options feel understandable | May feel impersonal |

These are examples, not mandatory aesthetics. Cultural context and audience can reverse the effect.

## 2. Reference analysis

For each reference record URL/file, access date, observed viewport/state, source type (live screen, image, editorial description), concrete feature, interpretation and relevance. Identify an application boundary: a campaign's dramatic typography may not suit a dense settings screen. Inspect motion and mobile behavior before making claims about them. Do not invent those observations from static images.

Use references to discover a relationship, such as “a product motif shapes section boundaries,” not to copy the distinctive silhouette, layout or assets. Original visual hypotheses are acceptable when research is unavailable. Record that distinction prominently, and never fabricate attribution or reuse rights.

## 3. Comparable screen proposals

Keep the same core content, required actions and viewport for the comparison. Vary at least two meaningful mechanisms: composition, type relationships, image treatment, shape language, content rhythm, navigation presentation or interaction emphasis. Preserve the actual task and avoid invented claims/testimonials/prices. Fictional examples must say so.

Create useful screens with realistic copy and hierarchy, not placeholder rectangles. Native HTML/CSS/SVG is suitable for layout, typography and diagrams; use image tools when photography, illustration or texture is essential and available. Do not require an external service. Label illustration as illustration rather than presenting it as a product photograph.

Inspect desktop and narrow output. Include an error, selected or expanded state when important. Keep visible focus, wrapping, accessible names, reduced-motion intent and contrast in view, while distinguishing static inspection from runtime or assistive testing. A proposed animation must specify purpose, trigger and reduced-motion alternative, not just “make it dynamic.”

## 4. Critique → refinement

Record a short critique of the actual output: strongest idea, distracting element, hierarchy weakness, mobile compromise and uncertainty. Retain the first rendering, then refine a provisional favorite. Compare the revised screen to its predecessor, naming what changed and what was preserved. Do not equate iteration count with quality.

Check whether deliberate inconsistencies serve a role. A contrasting display typeface can distinguish sections; a dense composition can express energy. Remove the variation only if it undermines task, meaning or readability. Show conflicting judgments rather than hiding them in a single score.

## 5. Handoff

Return a screen board, short recommendation, direction comparison and implementation notes (type roles, spacing, colors, component states, responsive changes, asset requirements). Include reference provenance and a limits statement. Keep detailed evidence outside the short chat summary.

When using DIF's full structured proposal contract, map screens and artifacts to stable IDs and existing evidence categories. Do not invent new schema fields or claim four-artifact completion for a visual study. A visual proposal can be useful without being a finalized package. Human adoption stays pending until actually supplied.
